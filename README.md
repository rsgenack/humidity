# SensorPush to BigQuery Historical Data Loader\n\nThis script fetches all available historical sensor data from the SensorPush API for a predefined set of sensors and loads it into a Google BigQuery table.\n\nIt handles:\n- Authentication with SensorPush.\n- Fetching data using pagination to retrieve all history.\n- Processing data (assigning names/rooms, converting humidity format).\n- Deduplicating data against existing records in BigQuery based on `sensor_name` and `observed` timestamp.\n- Inserting unique data into BigQuery in batches.\n\n## Prerequisites\n\n- Node.js (v16 or later recommended)\n- npm (usually included with Node.js)\n- Google Cloud SDK (`gcloud`) installed and configured (optional, but helpful for authentication)\n- A Google Cloud project with the BigQuery API enabled.\n- A BigQuery dataset and table created with the appropriate schema (see `fetch-all-sensorpush-to-bq.js` for expected fields like `observed`, `temperature`, `humidity_percent`, `dewpoint`, `vpd`, `sensor_name`, `room`).\n- A Google Cloud service account with permissions to write to the target BigQuery table (`BigQuery Data Editor` role is sufficient).\n\n## Configuration (Easy Setup)\n\nThere are two main things you need to configure after cloning this repository:\n\n**1. Sensor Mapping (`sensors.json`):**\n\n   - Find the `sensors.example.json` file in this repository.\n   - **Copy** this file and rename the copy to `sensors.json`.\n   - **Edit `sensors.json`**: \n     - For each sensor you want to track, create an entry (e.g., `"bedroom": { ... }`).\n     - Set the `"name"` field to the custom name you want to see in BigQuery (e.g., `"Bedroom Sensor"`).\n     - Set the `"id"` field to the **exact** SensorPush ID for that device.\n     - Set the `"room"` field to the desired room name.\n     - Add or remove entries to match the sensors you want to load data for.\n   - **Tip:** When you first run the script, it will attempt to list all sensors registered to your SensorPush account (names and IDs) in the log output. Use this list to easily find the correct IDs for your `sensors.json` file!\n   - **Important:** Do not commit your actual `sensors.json` file if you prefer to keep your specific sensor IDs private (though they are generally not considered secret).\n\n**2. Environment Variables:**\n\n   You **must** set the following environment variables before running the script:\n\n   *   `SENSORPUSH_EMAIL`: Your SensorPush account email address.\n   *   `SENSORPUSH_PASSWORD`: Your SensorPush account password.\n   *   `GOOGLE_APPLICATION_CREDENTIALS`: The **absolute path** to your downloaded Google Cloud service account JSON key file.\n\n   You **can optionally** set these environment variables to override the defaults configured in the script:\n\n   *   `GOOGLE_PROJECT_ID`: Your Google Cloud Project ID (Default: `savvy-fountain-431023-t4`).\n   *   `BIGQUERY_DATASET_ID`: The BigQuery Dataset ID to use (Default: `Humidity`).\n   *   `BIGQUERY_TABLE_ID`: The BigQuery Table ID to use (Default: `all_data`).\n   *   `BIGQUERY_BATCH_SIZE`: Number of rows per BigQuery insert batch (Default: `500`).\n   *   `SENSORPUSH_API_LIMIT`: Max samples per SensorPush API request (Default: `5000`).\n\n   **How to set environment variables (example for bash/zsh):** \n   ```bash\nexport SENSORPUSH_EMAIL="your_email@example.com"\nexport SENSORPUSH_PASSWORD="your_sensorpush_password"\nexport GOOGLE_APPLICATION_CREDENTIALS="/path/to/your/gcp-keyfile.json"\n# Optionally set others:\n# export GOOGLE_PROJECT_ID="your-gcp-project"\n```\n   *(Remember to replace placeholders with your actual values!)*\n\n## Installation\n\nNavigate to the script's directory in your terminal and install dependencies:\n\n```bash\nnpm install\n```\n\n## Running the Script\n\nOnce configured and dependencies are installed, run the script from its directory:\n\n```bash\n# Ensure environment variables are set in your current shell session!\nnpm start\n```\n\nor directly with Node.js:\n\n```bash\n# Ensure environment variables are set in your current shell session!\nnode fetch-all-sensorpush-to-bq.js\n```\n\nThe script will log its progress. Fetching all historical data can take a significant amount of time.\n\n## Docker\n\nA `Dockerfile` is included for containerization. \n\n- **Build:** `docker build -t sensorpush-loader .`\n- **Run:** You'll need to pass environment variables and mount your `sensors.json` and GCP credentials file into the container.\n  ```bash\ndocker run --rm \
    -e SENSORPUSH_EMAIL="$SENSORPUSH_EMAIL" \
    -e SENSORPUSH_PASSWORD="$SENSORPUSH_PASSWORD" \
    -e GOOGLE_APPLICATION_CREDENTIALS="/app/gcp-keyfile.json" \
    # Optional: Set GCP Project/Dataset/Table env vars here too \
    -v "$(pwd)/sensors.json:/usr/src/app/sensors.json" \
    -v "$GOOGLE_APPLICATION_CREDENTIALS:/app/gcp-keyfile.json" \
    sensorpush-loader\n```\n   *(Adjust volume paths (`-v`) as needed. This example assumes you run `docker run` from the project directory and your environment variables are already exported in your shell.)*\n\n## Important Notes\n\n*   **Execution Time:** Fetching large amounts of historical data can be very time-consuming.\n*   **API Limits:** Be mindful of SensorPush API rate limits.\n*   **BigQuery Costs:** Loading data and querying incurs BigQuery costs.\n*   **Idempotency:** The script aims to be mostly idempotent, preventing duplicate row insertions based on `sensor_name` and `observed` timestamp.
