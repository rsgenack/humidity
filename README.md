# SensorPush to BigQuery Historical Data Loader\n\nThis script fetches all available historical sensor data from the SensorPush API for a predefined set of sensors and loads it into a Google BigQuery table.\n\nIt handles:\n- Authentication with SensorPush.\n- Fetching data using pagination to retrieve all history.\n- Processing data (assigning names/rooms, converting humidity format).\n- Deduplicating data against existing records in BigQuery based on `sensor_name` and `observed` timestamp.\n- Inserting unique data into BigQuery in batches.\n\n## Prerequisites\n\n- Node.js (v16 or later recommended)\n- npm (usually included with Node.js)\n- Google Cloud SDK (`gcloud`) installed and configured (optional, but helpful for authentication)\n- A Google Cloud project with the BigQuery API enabled.\n- A BigQuery dataset and table created with the appropriate schema (see `fetch-all-sensorpush-to-bq.js` for expected fields like `observed`, `temperature`, `humidity_percent`, `dewpoint`, `vpd`, `sensor_name`, `room`).\n- A Google Cloud service account with permissions to write to the target BigQuery table (`BigQuery Data Editor` role is sufficient).\n\n## Setup\n\n1.  **Clone/Download:** Get the script files (`fetch-all-sensorpush-to-bq.js`, `package.json`).\n2.  **Install Dependencies:** Navigate to the script's directory in your terminal and run:\n    ```bash\n    npm install\n    ```\n3.  **Configure Authentication:**\n    *   **SensorPush:** Update the `SENSORPUSH_EMAIL` and `SENSORPUSH_PASSWORD` constants within `fetch-all-sensorpush-to-bq.js`. **(Recommended: Move these to environment variables for security)**.\n    *   **Google Cloud:** \n        *   Download the JSON key file for your service account.\n        *   Set the `GOOGLE_APPLICATION_CREDENTIALS` environment variable to the *absolute path* of this JSON key file. Example:\n          ```bash\n          export GOOGLE_APPLICATION_CREDENTIALS=\"/path/to/your/keyfile.json\"\n          ```\n        *   Alternatively, if running in a Google Cloud environment (like Cloud Functions, Compute Engine with service accounts), authentication might be handled automatically.\n4.  **Configure Script:**\n    *   Verify/update `GOOGLE_PROJECT_ID`, `BIGQUERY_DATASET_ID`, and `BIGQUERY_TABLE_ID` in `fetch-all-sensorpush-to-bq.js` to match your BigQuery setup.\n    *   Verify/update the `SENSOR_MAPPING` constant in the script to include all the sensors you want to fetch data for, along with their correct IDs and desired room names.\n\n## Running the Script\n\nOnce setup is complete, run the script from its directory using:\n\n```bash\nnpm start\n```\n\nor directly with Node.js:\n\n```bash\nnode fetch-all-sensorpush-to-bq.js\n```\n\nThe script will log its progress to the console. Fetching all historical data can take a significant amount of time depending on the data volume and API responsiveness.\n\n## Important Notes\n\n*   **Execution Time:** Fetching large amounts of historical data can be very time-consuming.\n*   **API Limits:** Be mindful of SensorPush API rate limits. If you encounter errors, you might need to add delays or retry logic (not currently implemented).\n*   **BigQuery Costs:** Loading large amounts of data and querying for deduplication incurs BigQuery costs.\n*   **Error Handling:** The script includes basic error handling, but complex scenarios (like partial batch failures needing specific recovery) might require more sophisticated logic.\n*   **Idempotency:** The deduplication logic aims to make the script *mostly* idempotent (running it multiple times won't insert duplicate rows), but relies on the accuracy of the `sensor_name` and `observed` timestamp fields.
